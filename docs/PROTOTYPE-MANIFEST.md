# Prototype Manifest — legacy/ui/index.html

Derived by reading the 638,779-byte prototype, not from its accompanying write-up.
This is the map the component split follows, so it records what the file *does*,
not what it aspires to.

## Shape

One self-contained HTML file: a `<style>` block (lines 10–190), a
`<script id="gamedata" type="application/json">` blob starting at line 201, and an
application script that renders by building HTML strings from template literals.

**There is no backend of any kind.** No `fetch`, no Supabase client, no network
call anywhere in the file. `userTeam` is hardcoded to `"DEN"`; the home header
string contains a literal `Week 18`. Nothing in the app can write anything.

## Screens

Eleven hand-written handlers on the `SCREENS` object:

| Key | Params | Reads | Shows |
|---|---|---|---|
| `home` | — | `D.standings`, `D.teams`, news | Contextual command centre: record, standings context, news |
| `team` | team id | roster, depth chart, team stats | Roster with four sort modes, depth chart, team statistics |
| `player` | player id | `D.profiles[id]` | Overview / Stats / Grades / Career / Honours |
| `league` | — | standings, grades, awards | Standings at three scopes, grade leaderboards by position |
| `allpro` | season | All-Pro selections | First and second teams by position |
| `allstar` | season | All-Star selections | Selections by conference |
| `award` | award, season | `award_voting` | Winner plus full ballot with vote bars |
| `history` | — | season history | League history by season |
| `records` | — | league records | Record book, split by competition |
| `search` | — | all 284 profiles | Search across players including retired |
| `inbox` | — | news | Tappable news headlines |

**Six further "screens" are generated by one loop**, not written individually:

```js
['trade','fa','draft','txn','staff','settings'].forEach(k => { ... })
```

over a table of title/message pairs. Each renders an honest message that the
feature is not built. The static flow test reporting "17 screens defined,
MISSING SCREENS: none" is technically true, but a third of that count is this loop.

Their messages, verbatim in intent:

- **trade** — "The trade engine is not built yet. Assets, valuation and cap impact land here."
- **fa** — "The free-agency market runs in the simulation engine but is not yet wired to this screen."
- **draft** — "Draft board, scouting uncertainty and pick trading land here."
- **txn** — "The ledger exists in the engine. This screen is not wired to it yet."
- **staff** — "Coaching profiles, contracts and coaching trees land here."
- **settings** — "Gameplay, simulation, display and accessibility settings land here."

The cap screen shows placeholder figures and says so; the contract engine exists
but is not wired to it.

## Navigation

Three primitives, found at these offsets:

- `function push(screen, params = ...)`
- `function back()` — restores frame UI state (`restore` helper nearby)
- `function replaceRoot(screen, params = ...)`

**There is no `openPlayer(id)`.** Entity navigation is hand-written inline
`push('player',{id})` inside `onclick` attributes embedded in template literals.
The behaviour is correct today; there is no seam. That is why
`src/app/entity.ts` and `<EntityLink>` exist before any screen is rebuilt.

## Known defects carried in the prototype

1. **Search refocus hack** — the whole view re-renders on state change, destroying
   input focus, patched by re-focusing on each keystroke via `setTimeout`.
2. **Depth chart reordering not implemented** — tapping opens the profile instead
   of swapping.
3. **Full re-render on every state change** — will not survive a long save.
4. **One file** — markup, styles, data and logic together.

## Data defects visible in the embedded snapshot

- Many profiles carry `"ovr": null, "age": null` (P-prefixed engine-generated
  players with no row in the seed CSVs).
- Some profiles carry `"team": ""` for retired or unsigned players.
- Kicker `longest_fg` holds season sums: 563, 618, 720 appear.

Fix these in the engine's export path, never in the interface.
